## Recovery hazard discovered in primary maintainer notes

The maintainer of the [A145P TWRP recovery tree](https://github.com/forforksake/recovery_device_samsung_a14m/releases/tag/TWRP_3.7.0_12_2_CFKod) explicitly **withdrew `twrp_08092023-2358.img`**, advising against its use, especially for backup/restore. They described fstab-related mount/restore failures, an `fs_mgr_mount_all` Android rescue error and unsuccessful restoration attempts. The published [earlier TWRP build](https://github.com/forforksake/recovery_device_samsung_a14m/releases/tag/TWRP_3.7.0_12-SM-A145P) is a distinct release and contains recovery ADB/touchscreen observations; neither release identifies the currently installed version on this phone.

**Response:** `mobile/tools/a14m_twrp_recovery_gate.py` has been extended to return `known_historical_recovery_warning` with `applies_to_installed_twrp=UNKNOWN` and a new blocker `INSTALLED_TWRP_LINEAGE_NOT_VERIFIED_AGAINST_WITHDRAWN_FSTAB_BUILD`; `mobile/tests/test_a14m_twrp_recovery_gate.py` has a negative/unknown-lineage assertion. This prevents the source-only gate from equating visible TWRP with a proven rollback route. The existing `recovery.fstab` and PIT still show separate *historical* boot/recovery partitions, but **separation does not prove restored boot capability**.

## What is and is not established

**Established:** KRATOS online and Oracle terminal operational; Ptah native analyzer worked on the exact staged Core image; image section integrity; historical MT6768 source DTB; immutable Core staging provenance; recovery-specific historical maintainer risk captured.

**Not established:** current SM-A145P connected over USB; exact installed TWRP build/hash; current phone's boot, recovery, `vbmeta`, `vendor_boot` or `init_boot` contents; backup/restore rehearsal; active bootloader/AVB state; full Prime Mobile UI, production persistent Core or physical display/touch/modem; actual physical first boot. KRATOS and ATHENA both had empty ADB device lists at the last check. No flash, reboot, installer or phone partition change has been performed.

**Engineering disposition:** `SOURCE_IMAGE_STRUCTURE_PASSED / PHYSICAL_DEVICE_ADMISSION_BLOCKED`. Keep PR #223 draft and the staged image non-flashable. The first hardware acceptance action is a read-only inventory of the actual TWRP-only device and verification of a recoverable return-to-TWRP/stock path; do not assume that this withdrawn historical TWRP build is what's installed. Do not request another intermediate ZIP from the user. All work remains in the **single Prime-OS repository**.
